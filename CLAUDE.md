# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A Corporate Memory (CMEM) marketplace package of type `project` that ships
[Sparnatural](https://sparnatural.eu/) as a static page served from a Build project, plus an application view
(*Search*) that opens it. There is **no server-side component, no Python plugin, no npm dependency** — the page
generates its own Sparnatural configuration in the browser from the data of the selected graph and from the CMEM
shapes catalog.

Read [DOCUMENTATION.md](DOCUMENTATION.md) for the user-visible behaviour (parameters, modes, maps, cache) and
[docs/superpowers/specs/2026-11-25-sparnatural-package-design.md](docs/superpowers/specs/2026-11-25-sparnatural-package-design.md)
for the design decisions and the verified CMEM constraints behind them.

## Commands

Root [Taskfile.yaml](Taskfile.yaml) handles the package, `src/Taskfile.yml` the page. Root tasks delegate with
`cd src`.

```bash
task test                      # unit tests (node >= 20, no npm install)
task build                     # build-project, then `cmemc package build` into dist/
task check                     # build, install into CMEM, uninstall again
task publish                   # publish dist/*.cpa to the marketplace
task                           # list all tasks

cd src
node --test test/config.test.js                    # one test file
node --test --test-name-pattern 'shapes mode'      # one test by name
task build-html                # stamp __BUILD_ID__ and collect served files in src/dist/
bash scripts/dev-upload.sh     # upload src/dist/ into the installed project (current cmemc connection);
                               # CHANGED_ONLY=1 skips vendor/ — the fast loop for browser checks
bash scripts/record-fixtures.sh  # re-record test/fixtures/*.json (needs the product data demo package)
task vendor                    # re-download pinned third-party files (only to change a version)
```

`Taskfile.yaml`, `.copier-answers.*` are generated by the
[copier template](https://github.com/eccenca/cmem-package-template) — don't edit them; put additions in
`TaskfileCustom.yaml`.

## Architecture

### Load pipeline

`src/sparnatural-app.js` is DOM glue only; every rule lives in a tested module under `src/lib/`:

1. `params.readParams()` — hash (`#graph=…`) wins over query (`?graph=…`).
2. `cache.cacheKey()` over (build id, user IRI from `/dataplatform/userinfo`, graph, mode, lang) →
   `localStorage` hit returns the cached Turtle (24 h). An unknown user yields a `null` key, so nothing is cached.
3. `stats.collectStats()` — classes with instance counts, their properties with observed ranges, labels,
   `foaf:depiction`; progress reported per step.
4. `shapes.loadShapesOrNote()` — node/property shapes of the central catalog `https://vocab.eccenca.com/shacl/`
   for exactly those classes (skipped in mode `raw`); any failure degrades to statistics plus a note.
5. `config.buildModel()` — **all-or-nothing mode decision**: one applicable node shape switches the whole graph to
   `shapes` mode (unshaped classes and properties are then hidden); otherwise `statistics` mode; no classes →
   `empty`. Then `config.toTurtle()` writes Sparnatural's SHACL vocabulary.
6. The Turtle goes into a `blob:` URL as the `src` of a `<spar-natural>` element; the `endpoint` attribute carries
   `?default-graph-uri=<graph>`, and the CMEM endpoint expands that to the `owl:imports` closure.
7. Results render in Yasr with the vendored `TableX` and `Map` plugins; `links.js` builds the per-resource link
   targets from URL templates with `{view}`, `{graph}`, `{resource}`.

All SPARQL runs through `sparql.makeExecutor(fetch)` against `/dataplatform/proxy/default/sparql` with
`credentials: 'same-origin'` — the logged-in user's own access rights, no tokens. The executor is injected
everywhere, which is what makes the modules testable against recorded fixtures without a CMEM instance.

### Dual-target modules

Each `src/lib/*.js` is a small UMD wrapper: `module.exports` in node, `window.CmemSparnatural.<name>` in the
browser, with dependencies resolved the same way in both. Keep that shape when adding a module, and add its
`<script>` to `src/sparnatural.html` (order matters — dependencies first).

### Build and generated files

`scripts/embed-build-metadata.sh` replaces the `__BUILD_ID__` marker in `sparnatural.html` and
`sparnatural-app.js` with `git describe` (it is also the cache-busting `?v=` and part of the cache key), then
copies the served files into `src/dist/`. `task build-project` wipes
`sparnagit-sparnatural-service-project/projects/sparnatural-service/resources/` and refills it from `src/dist/`,
and stamps the version into the `<Label>` of that project's `config.xml`.

Never edit `src/dist/` or `projects/sparnatural-service/resources/` — both are generated (and gitignored).
`config.xml`, `tags.xml` and `variables.xml` next to `resources/` are committed content.
`views/sparnatural.json` is exported from a live instance (`cmemc admin view export sparnatural`) and committed.

## Things to keep intact

- **No npm, no build step beyond `sed` and `cp`.** Plain ES in browsers and node ≥ 20, `node:test` only.
- **Vendored third-party files** (`src/vendor/`) are unmodified and pinned by checksum in `scripts/vendor.sh`.
  Sparnatural is LGPL-3.0 while this package is Apache-2.0: its files must stay separate under
  `vendor/sparnatural/` with their license texts and must never be merged into our own JS. Update
  `src/vendor/NOTICE.md` and the third-party table in DOCUMENTATION.md with every version change.
- **Escaping.** Sparnatural's widgets and TableX insert label values into HTML unescaped. Three places compensate:
  `sparql.neutralizeLiterals()` for widget queries, `links.safeBindingSet` for result tables, and
  `links.parseLinks()`, which accepts only local paths and `http(s)` templates. `config.toTurtle` escapes IRIs and
  literals for the generated Turtle. Don't bypass them.
- **Version scheme**: Sparnatural's version plus a package revision, e.g. `14.1.0-1`. Releases are tags
  (`git describe` feeds the build), the changelog follows
  [Keep a Changelog](http://keepachangelog.com/) with an `[Unreleased]` section.
- Workarounds exist for pinned-version quirks and are commented as such: `mapquery.toV13Query()` converts
  Sparnatural 14's query JSON for the older Map plugin, a `MutationObserver` adds `step="any"` to number inputs,
  another adds the extra link chips after `a.iri`. They depend on the pinned markup — check them after a
  Sparnatural upgrade.
- `theme.js` copies the parent CMEM page's `--eccgui-*` tokens onto the page; every Sparnatural variable in
  `sparnatural-theme-cmem.css` must keep a hex fallback for standalone use (a test enforces this).
